## Root Causes Identified

### 1. Algorithm Precondition Violation
- Dijkstra's algorithm does NOT support negative-weight edges
- Code doesn't check for negative weights before running Dijkstra
- When negative weights exist, Dijkstra produces incorrect results

### 2. Implementation Bug in routing.py
- **Premature Visit Marking**: Nodes are marked as visited when discovered, not when finalized from priority queue
- This prevents re-relaxation of visited nodes even when better paths are found
- Buggy code pattern:
  ```python
  visited = set([start])  # Mark start immediately
  ...
  visited.add(neighbor)   # Mark neighbor on discovery, not finalization
  ```

### 3. Missing Input Validation
- No detection of negative-weight edges before algorithm execution
- No alternative algorithm provided (e.g., Bellman-Ford) for negative-weight graphs

### 4.2 Implement Bellman-Ford Algorithm

1. **Create new function `bellman_ford_shortest_path(graph, start, end)`**:
   
   **Algorithm Overview**:
   - Time complexity: O(V × E) - slower than Dijkstra but supports negative weights
   - Relaxes all edges V-1 times (V = number of vertices)
   - Detects negative-weight cycles on Vth iteration
   
   **Implementation Requirements**:
   ```python
   def bellman_ford_shortest_path(graph, start, end):
       """
       Find shortest path using Bellman-Ford algorithm.
       Supports negative-weight edges but not negative-weight cycles.
       
       Returns: (path_list, total_cost)
       Raises: ValueError if negative-weight cycle detected
       """
       # 1. Initialize distances (all infinity except start=0)
       # 2. Get all vertices from graph
       # 3. Relax all edges V-1 times
       # 4. Check for negative cycles (Vth iteration)
       # 5. Reconstruct path from start to end
       # 6. Return (path, cost)
   ```

   **Key Implementation Details**:
   - Initialize: `distances = {node: float('inf') for all nodes}`, `distances[start] = 0`
   - Track predecessors: `predecessor = {node: None for all nodes}`
   - Relax edges: For each edge (u, v, w), if `distances[u] + w < distances[v]`, update both `distances[v]` and `predecessor[v]`
   - Negative cycle detection: After V-1 iterations, check if any edge can still be relaxed
   - Path reconstruction: Walk backwards from `end` using `predecessor` dictionary

## Critical Implementation Notes

### Dijkstra Visit Marking Fix (Most Important Bug)
- **Bug Pattern**: `visited.add(neighbor)` during neighbor exploration
- **Fix Pattern**: 
  ```python
  current_cost, current_node = heapq.heappop(priority_queue)
  if current_node in visited:
      continue
  visited.add(current_node)  # Mark when popped (finalized)
  ```
- **Rationale**: Nodes should be marked as "finalized" only when their minimum distance is confirmed (when popped from priority queue), not when first discovered

### Bellman-Ford Relaxation
- **Relaxation Condition**: `if distances[u] + weight < distances[v]:`
- **Update Operations**: Update both `distances[v]` and `predecessor[v]`
- **Iteration Count**: Exactly V-1 iterations (V = number of vertices)
- **Cycle Detection**: If any edge can be relaxed on Vth iteration, negative cycle exists
