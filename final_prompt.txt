```python
def bellman_ford_shortest_path(graph: Graph, start: str, goal: str) -> Tuple[List[str], float]:
    """
    Find shortest path using Bellman-Ford algorithm (supports negative weights).
    
    Args:
        graph: Graph instance
        start: Starting node
        goal: Goal node
    
    Returns:
        Tuple of (path, cost)
        
    Raises:
        ValueError: If negative cycle detected or goal unreachable
    """
    # Initialize distances
    distances = {node: float('inf') for node in graph.get_all_nodes()}
    distances[start] = 0
    predecessors = {node: None for node in graph.get_all_nodes()}
    
    # Relax edges V-1 times
    nodes = list(graph.get_all_nodes())
    for _ in range(len(nodes) - 1):
        for node in nodes:
            if distances[node] == float('inf'):
                continue
            for neighbor, weight in graph.get_neighbors(node):
                new_distance = distances[node] + weight
                if new_distance < distances[neighbor]:
                    distances[neighbor] = new_distance
                    predecessors[neighbor] = node
    
    # Check for negative cycles
    for node in nodes:
        if distances[node] == float('inf'):
            continue
        for neighbor, weight in graph.get_neighbors(node):
            if distances[node] + weight < distances[neighbor]:
                raise ValueError("Negative weight cycle detected")
    
    # Check if goal is reachable
    if distances[goal] == float('inf'):
        raise ValueError(f"No path from {start} to {goal}")
    
    # Reconstruct path
    path = []
    current = goal
    while current is not None:
        path.append(current)
        current = predecessors[current]
    path.reverse()
    
    return path, distances[goal]
```

# Critical Notes

## Algorithm Selection Rationale

**Why Bellman-Ford for Negative Weights?**
- Dijkstra's greedy approach fails with negative weights
- Once a node is finalized in Dijkstra, it's never reconsidered
- Negative edges can create shorter paths to already-finalized nodes
- Bellman-Ford relaxes all edges V-1 times, allowing reconsideration
- Trade-off: Slower (O(V×E) vs O((V+E)log V)) but correct for negative weights

## Common Pitfalls to Avoid

1. **Don't just add validation without fixing algorithm**: Tests expect correct path, not just error
2. **Don't modify visit marking without understanding**: The bug is subtle but critical
3. **Don't forget path reconstruction**: Bellman-Ford needs proper predecessor tracking
4. **Don't skip negative cycle detection**: Required for Bellman-Ford correctness
5. **Don't change test files**: Tests are correct; fix the implementation
