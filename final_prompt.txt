# Critical Implementation Notes

## Dijkstra Bug Fix Details

**Original buggy pattern:**
```python
visited = set([start])  # BUG: Mark start immediately

while pq:
    current_distance, current_node = heapq.heappop(pq)
    
    for neighbor, weight in graph.get_neighbors(current_node):
        if neighbor in visited:
            continue
        new_distance = current_distance + weight
        if new_distance < distances[neighbor]:
            distances[neighbor] = new_distance
            predecessors[neighbor] = current_node
            heapq.heappush(pq, (new_distance, neighbor))
            visited.add(neighbor)  # BUG: Mark when discovered
```

**Fixed pattern:**
```python
visited = set()  # FIX: Don't mark start immediately

while pq:
    current_distance, current_node = heapq.heappop(pq)
    
    # FIX: Mark as visited when finalized (popped)
    if current_node in visited:
        continue
    visited.add(current_node)
    
    if current_node == goal:
        break  # Early exit
    
    for neighbor, weight in graph.get_neighbors(current_node):
        if neighbor in visited:
            continue
        new_distance = current_distance + weight
        if new_distance < distances[neighbor]:
            distances[neighbor] = new_distance
            predecessors[neighbor] = current_node
            heapq.heappush(pq, (new_distance, neighbor))
            # FIX: Don't mark visited here
```

## Algorithm Selection Rationale

**Why Bellman-Ford for Negative Weights:**
- Dijkstra's greedy approach fails with negative weights
- Once a node is finalized in Dijkstra, it's never reconsidered
- Negative edges can create shorter paths to already-finalized nodes
- Bellman-Ford relaxes all edges V-1 times, allowing reconsideration
- Trade-off: Slower O(V×E) vs. O((V+E)log V), but correct for negative weights

## Expected Execution Flow

1. User calls `shortest_path(graph, 'A', 'B')`
2. Function calls `has_negative_weights(graph)`
3. Scans all edges, finds D→F with weight -3
4. Returns `True` (negative weights detected)
5. `shortest_path()` switches to `bellman_ford_shortest_path(graph, 'A', 'B')`
6. Bellman-Ford relaxes edges V-1 times
7. Finds optimal path: A→C (2) → D (1) → F (-3) → B (1) = **1.0**
8. Returns `(['A', 'C', 'D', 'F', 'B'], 1.0)`

## Common Pitfalls to Avoid

1. **Don't just add validation without fixing algorithm** - Tests expect correct path, not just error detection
2. **Don't modify visit marking without understanding** - The bug is subtle but critical
3. **Don't forget path reconstruction** - Must reverse the path after following predecessors
4. **Don't skip edge cases** - Self-loops, unreachable nodes, start==goal all must work
5. **Don't change test expectations** - The tests define the correct behavior
