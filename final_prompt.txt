## Root Causes Identified

### 1. Algorithm Precondition Violation
- Dijkstra's algorithm does NOT support negative-weight edges
- Code doesn't check for negative weights before running Dijkstra
- When negative weights exist, Dijkstra produces incorrect results

### 2. Implementation Bug in routing.py
- **Premature Visit Marking**: Nodes are marked as visited when discovered (line 23), not when finalized from priority queue
- This prevents re-relaxation of visited nodes even when better paths are found
- Buggy code pattern:
  ```python
  visited = set([start])  # Mark start immediately
  ...
  visited.add(neighbor)   # Mark neighbor on discovery, not finalization
  ```

### 3. Missing Input Validation
- No detection of negative-weight edges before algorithm execution
- No alternative algorithm provided (e.g., Bellman-Ford) for negative-weight graphs

### 4.2 Implement Bellman-Ford Algorithm

1. **Create new function `bellman_ford_shortest_path(graph, start, end)`**:
   
   **Algorithm Overview**:
   - Time complexity: O(V × E) - slower than Dijkstra but supports negative weights
   - Relaxes all edges V-1 times (V = number of vertices)
   - Detects negative-weight cycles on Vth iteration
   
   **Implementation Requirements**:
   ```python
   def bellman_ford_shortest_path(graph, start, end):
       """
       Find shortest path using Bellman-Ford algorithm.
       Supports negative-weight edges but not negative-weight cycles.
       
       Returns: (path_list, total_cost)
       Raises: ValueError if negative-weight cycle detected
       """
       # 1. Initialize distances (all infinity except start=0)
       # 2. Relax all edges V-1 times
       # 3. Check for negative cycles (Vth iteration)
       # 4. Reconstruct path from start to end
       # 5. Return (path, cost)
   ```

   **Key Implementation Details**:
   - Initialize: `distances = {node: float('inf') for all nodes}`, `distances[start] = 0`
   - Relax edges: For each edge (u, v, w), if `distances[u] + w < distances[v]`, update `distances[v]`
   - Negative cycle detection: If any edge can still be relaxed on Vth iteration, cycle exists
   - Path reconstruction: Track `predecessor` dictionary during relaxation

### 4.3 Implement Auto Algorithm Selector

   **Implementation**:
   ```python
   def shortest_path(graph, start, end, algorithm='auto'):
       """
       Find shortest path with automatic or manual algorithm selection.
       
       Args:
           graph: Graph instance
           start: Starting node
           end: Destination node
           algorithm: 'auto', 'dijkstra', or 'bellman_ford'
       
       Returns: (path_list, total_cost)
       """
       if algorithm == 'auto':
           # Auto-select based on graph characteristics
           if graph.has_negative_weights():
               return bellman_ford_shortest_path(graph, start, end)
           else:
               return dijkstra_shortest_path(graph, start, end)
       elif algorithm == 'dijkstra':
           return dijkstra_shortest_path(graph, start, end)
       elif algorithm == 'bellman_ford':
           return bellman_ford_shortest_path(graph, start, end)
       else:
           raise ValueError(f"Unknown algorithm: {algorithm}")
   ```

## Critical Implementation Notes

### Dijkstra Visit Marking Fix
- **Bug Pattern**: `visited.add(neighbor)` during neighbor exploration
- **Fix Pattern**: `visited.add(current_node)` when popping from priority queue
- **Rationale**: Nodes should be marked as "finalized" only when their minimum distance is confirmed, not when first discovered

### Bellman-Ford Relaxation
- **Relaxation Condition**: `if distances[u] + weight < distances[v]:`
- **Update Operations**: `distances[v] = distances[u] + weight`, `predecessor[v] = u`
- **Iteration Count**: Exactly V-1 iterations (V = number of vertices)
- **Cycle Detection**: If any edge can be relaxed on Vth iteration, negative cycle exists

### Algorithm Selection Logic
```python
if algorithm == 'auto':
    if graph.has_negative_weights():
        use Bellman-Ford  # Slower but handles negatives
    else:
        use Dijkstra      # Faster for non-negative graphs
```
